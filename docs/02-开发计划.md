# DSH 多租户多实例管理器 · 开发计划

> 版本 v1（2026-08-22）。前置阅读：`docs/01-调研笔记.md`（本计划所有技术判断的事实依据）。
> 项目暂名 **DSH Hub**。目标：一台 Linux 服务器，多人各自登录、互不干扰地使用 DeepSeek Harness 实例。

---

## 1. 目标与范围

### 1.1 目标（本期必做）

1. **网页登录**：注册/登录借鉴 new-api（session cookie + 角色三级 + 注册开关）；首启向导借鉴 sub2api（无任何账号时进入初始化向导创建管理员，此后入口失效）；首个注册的普通账号自动 root 作兜底；
2. **昵称目录**：用户账号创建成功后，在数据根下创建以其昵称命名的目录；该用户之后新建的所有实例、实例产生的全部数据（DSH_HOME、workspace、日志）都只落在这个目录内；
3. **实例隔离**：同一用户的多个实例之间，独立 DSH_HOME + 独立端口 + 独立 workspace + 实例锁，互不可见（沿用 DshController 模型）；
4. **用户间严格隔离**：不同用户的数据目录（700）、进程（独立进程组）、网络（实例仅绑 127.0.0.1，唯一公网入口是带鉴权的网关，网关校验所有权）、凭据（各用户目录内 600）四层隔离；提供"严格模式"（每用户独立 Unix 账号 + setuid 运行）作为可选强化；
5. **管理员后台**：管理所有用户（建号/禁用/重置密码/配额）与所有实例（跨用户查看、启停、强杀、删除、清理孤儿数据）、端口池、版本白名单、审计日志。

### 1.2 非目标（本期不做）

- 容器级隔离（远期可选）；计费/充值；多节点调度（单机版）；dsh 本体改造（不改 dsh 源码）；企业 SSO（预留不做）。

## 2. 总体架构

```
                       ┌────────────────────────────────────────────┐
  浏览器               │              Linux 服务器                   │
  ┌──────────┐  TLS   │  ┌─────────┐    ┌──────────────────────┐   │
  │ 用户 A    │───────▶│  │  Caddy  │───▶│  DSH Hub 控制面       │   │
  │ (dsh UI) │◀───────│  │ (TLS/   │    │  (Node.js 24, TS)    │   │
  └──────────┘  WS    │  │ 泛域名) │    │ ┌──────────────────┐ │   │
  ┌──────────┐        │  └─────────┘    │ │ 管理面 API/UI     │ │   │
  │ 管理员    │───────▶│        │        │ │ 鉴权网关(反代+WS) │ │   │
  └──────────┘        │        │        │ │ 实例监督器        │ │   │
                      │        ▼        │ │ (spawn/探活/停止) │ │   │
                      │  127.0.0.1:3080+│ └──────────────────┘ │   │
                      │  ┌──────────┐   │        │ SQLite(WAL)  │   │
                      │  │ dsh web  │◀──┼────────┘              │   │
                      │  │ 实例 A-1 │   └──────────────────────┘   │
                      │  ├──────────┤                               │
                      │  │ dsh web  │                               │
                      │  │ 实例 A-2 │    /srv/dshhub/               │
                      │  ├──────────┤     ├─ data/dshhub.db         │
                      │  │ dsh web  │     └─ users/                 │
                      │  │ 实例 B-1 │         ├─ 张三/   (700)      │
                      │  └──────────┘         │   ├─ <实例>/home/    │
                      │   (仅回环，无鉴权，    │   │   ├─ workspace/  │
                      │    外部不可直达)      │   │   └─ logs/       │
                      │                       │   └─ shared/         │
                      │                       └─ 李四/   (700)      │
                      └────────────────────────────────────────────┘
```

三个内部模块：

- **控制面 API**：用户/会话/实例的 CRUD 与生命周期指令，唯一写 SQLite 的组件；
- **鉴权网关**：唯一公网 HTTP 入口。管理面路径（/login、/api、/admin）与实例流量（按 Host 或专用端口识别）共用一个进程；对实例流量先验会话、再验所有权，然后反向代理（含 WebSocket）到 127.0.0.1:port；
- **实例监督器**：spawn `dsh web`（独立进程组）、TCP 就绪探测、TERM→KILL 停止、崩溃检测与可选自动重启、日志落盘、状态上报 DB。

## 3. 核心设计

### 3.1 用户与昵称目录（需求 2 的落地）

- 建号成功时（而非首次登录时——避免"登录了但建目录失败"的中间态）事务性地：
  1. 由昵称生成目录名：Unicode 保留（中文昵称直接作目录名，ext4 无碍），净化规则：剔除 `/`、控制字符、首尾空白与前导 `.`，长度截断 ≤64 字节，空结果回退 `user-<id8>`；
  2. 冲突处理：与现有目录重名时追加 `-2`、`-3`…（昵称本身在 DB 中保持唯一，目录名只是存储标签）；
  3. `mkdir -p users/<目录名>` 并 `chmod 700`（严格模式下 chown 到该用户的 Unix 账号）；
  4. DB 写入 `users.dir_name`。昵称改名 = 停掉该用户全部实例 → `rename()` → 更新 DB。**改名默认不允许，管理员操作才放开**，降低迁移风险。

目录布局（每用户、每实例）：

```
users/<昵称目录>/
  shared/                      # 用户级共享文件区（可选，M5）
  instances/<实例ID>/
    home/          # = DSH_HOME（profiles/ sessions/ storages/ settings.yaml .credentials.yaml）
    workspace/     # = dsh 进程 cwd，默认工作区根
    logs/          # web.out.log（轮转）、start-fail-<时间戳>.md（失败快照）
    instance.json  # 实例元数据本地镜像（DB 损坏时可恢复）
```

### 3.2 实例模型

沿用 DshController 的 InstanceDef，服务端版字段：

```jsonc
{
  "id": "i-9f3k2a",              // 短随机 ID，目录名与 URL 都用它（不用昵称，避免改名连锁）
  "ownerId": 7,
  "name": "我的主力实例",
  "port": 3121,                  // 由全局 PortAllocator 分配，DB 记账 + 探测双保险
  "harnessVersion": "0.1.1-rc.2",// 空 = 管理员默认版本；npx 拉取，免全局安装
  "trustedHost": "zhangsan-i9f3k2a.dsh.example.com",
  "status": "stopped|starting|running|stopping|failed",
  "pid": 12345, "startedAt": null,
  "autoRestart": false,
  "quota": { "memMaxMb": 4096, "cpuQuotaPct": 200 }   // M5 生效
}
```

启动命令（监督器执行，setsid 独立进程组，env 注入 DSH_HOME，cwd=workspace）：

```
dsh web --host 127.0.0.1 --port 3121 --trusted-host zhangsan-i9f3k2a.dsh.example.com --no-open
# harnessVersion 非空时改为: npx --yes @deepseek-ai/dsh@<版本> web ...
```

生命周期状态机复刻 DshController：Stopped → Starting（TCP 探活，超时 180s）→ Running；停止 = 杀进程组 TERM→8s→KILL → 确认端口释放；pidfile + `.dsh-instance.lock` 防重拉；启动失败生成 Markdown 快照。

### 3.3 隔离矩阵（需求 3、4 的验收口径）

| 维度 | 同用户实例间 | 不同用户间 | 实现手段 |
|---|---|---|---|
| 文件 | 完全独立 | 完全独立 | 独立 DSH_HOME/workspace；用户根 700；URL/目录用不可预测的实例 ID |
| 进程 | 独立进程组 | 独立进程组（严格模式：不同 uid） | setsid + pidfile + lock；严格模式 setuid 到 per-user Unix 账号 |
| 网络 | 独立端口，仅回环 | 互不可达 | dsh 只绑 127.0.0.1（其本身拒绝 0.0.0.0）；公网仅网关；防火墙只放网关+SSH |
| 访问控制 | — | 越权一律 404（不泄露存在性） | 网关校验 session → 校验 instance.ownerId == session.userId；admin 访问他人实例需"接管模式"显式开启并记审计 |
| 凭据 | 各实例独立 | 各用户独立 | `.credentials.yaml` 在各自 home 内 600；管理员可注入模板（复制后 600） |
| 资源 | 配额按实例 | 配额按用户汇总 | M5：systemd-run --scope MemoryMax/CPUQuota/PidsLimit |
| 会话数据 | 独立 | 独立 | dsh 会话按 HOME 天然隔离（调研 §1） |

### 3.4 认证与会话（借鉴 new-api + sub2api）

- **首启向导**（sub2api 式）：DB 无用户时，首个访问者进入 `/setup` 创建管理员；此后该入口永久失效；若开放注册，**第一个注册的普通账号自动 root**（new-api 式）作兜底——两者只生效其一；
- **角色**：root（可管理管理员）/ admin（用户与实例全权管理）/ user（仅自己的资源）；
- **注册开关**：open / closed（默认 closed，仅管理员建号）；**密码哈希**：M1 已落地为 Node 内置 scrypt（N=2^15,r=8,p=1，零依赖）；argon2id 记为 M5 加固项（npm 可达时可引入）；登录失败限速（5 次锁 15 分钟，进程内，M5 可落库）；
- **会话**：服务端 session（SQLite 存储），cookie HttpOnly + SameSite=Lax + Secure(Caddy 后)，滑动过期 7 天；管理面写操作叠加 CSRF token；
- **API token**（sub2api 式双轨）：用户可在设置页签发个人 token 供脚本调用管理 API（Bearer 头），可吊销；
- 后续可平滑换接 OIDC/OAuth（接口层留 AuthProvider 抽象，本期只实现密码登录）。

### 3.5 鉴权网关

- 路由模式 A（子域名，首选）：`<用户slug>-<实例ID>.dsh.example.com` → 查 DB 得实例与 owner → 校验会话所有权 → 反代 127.0.0.1:port；
- 路由模式 C（兜底）：网关在公网口为运行中实例按需开监听端口，校验逻辑相同；
- 代理要点（M0/S1 实证修订，见 docs/03）：**WS 隧道必需**——dsh 传输为「单次 RPC = HTTP POST /api/<method>」+「长连接事件流 = **WebSocket** /api/events.mux、/api/events.host」（普通 GET 回 426）；`--trusted-host` 为**精确全等**匹配（须逐实例传完整子域）；Host 头原样转发；X-Forwarded-* 注入；实例未运行时返回引导页（一键"启动实例"）；
- **特权方法回环钉死**（M0/S2 新发现）：settings.*/credentials.*/agentPreset.*/host.pickDirectory/llm.discoverModels 即使配了 trusted-host 也只认回环 → 域模式下这些方法 403。处理：默认走「管理员模板注入/环境变量桥」供给凭据（见 §3.6），M3 实测「Host 重写回 127.0.0.1 + 剥离 Origin」是否放行（注意同时废 dsh 自身同源 CSRF，靠网关会话/CSRF 顶上，需文档明示）；
- 管理面与实例流量同进程不同路由键；管理面路径永不代理到实例。

### 3.6 凭据供给（多用户部署的现实问题）

每个实例的 DSH_HOME 需要模型凭据才能工作。三种模式（全局默认 + 实例可覆盖）：

1. **用户自填**（原默认——M0/S2 修正后受限）：dsh UI 内改凭据走 credentials.* 特权方法，多用户域模式下 403 ⇒ 仅当用户与实例同机回环访问时可用；正式部署下不作为默认；
2. **管理员模板注入**（M0/S2 修正后**默认**）：管理员维护模板 settings.yaml + .credentials.yaml，新实例创建时复制并 chmod 600（复刻 DshController 的 WSL 凭据同步）；适合统一用服务器账号的小团队；与 dsh「配置面保持回环直到真实鉴权层出现」的设计自洽；
3. **环境变量桥**（推荐给用户自填场景）：实例 env 注入 key，settings 用 apiKeyEnv 引用（本机 settings.yaml 已见 apiKeyEnv 字段，可行）——不经 /api 特权方法，域模式下可用。

### 3.7 管理员后台功能清单（需求 5）

| 分组 | 功能 |
|---|---|
| 用户管理 | 列表/搜索；建号；禁用/启用（禁用即杀其全部实例并拒绝登录）；重置密码；改角色；改昵称（触发目录迁移）；删除（软删→归档目录→定期物理清理） |
| 配额 | 每用户：最大实例数、最大并发运行数、单实例内存/CPU 限额（M5） |
| 实例总览 | 跨用户实例表（属主/名称/端口/版本/状态/资源）；启停/重启/强杀；删除（连同目录）；日志查看（尾部 200 行） |
| 运维 | 端口池查看与回收；孤儿目录扫描（有目录无 DB 记录 / 有 DB 无目录）；磁盘用量统计（du 缓存）；失败快照浏览 |
| 全局设置 | 注册开关；默认 harness 版本与版本白名单（npm view 拉取）；路由模式与子域后缀；凭据供给模式与模板管理；会话有效期 |
| 审计 | 登录/建号/实例生命周期/接管访问/设置变更全量记录，可按用户/动作/时间过滤 |

## 4. 数据模型

```sql
users(id INTEGER PK, nickname TEXT UNIQUE, dir_name TEXT UNIQUE, email TEXT UNIQUE,
      password_hash TEXT, role TEXT CHECK(role IN ('user','admin','root')),
      status TEXT CHECK(status IN ('active','disabled')),
      max_instances INT DEFAULT 3, max_running INT DEFAULT 1,
      created_at INT, last_login_at INT)
sessions(id TEXT PK, user_id INT REF, token_hash TEXT, expires_at INT, created_at INT, ip TEXT, ua TEXT)
api_tokens(id INTEGER PK, user_id INT REF, name TEXT, token_hash TEXT, created_at INT, revoked_at INT)
instances(id TEXT PK, owner_id INT REF, name TEXT, port INT UNIQUE,
          home_path TEXT, workspace_path TEXT, harness_version TEXT, trusted_host TEXT,
          status TEXT, pid INT, auto_restart INT, mem_max_mb INT, cpu_quota_pct INT,
          created_at INT, last_started_at INT)
audit_logs(id INTEGER PK, actor_id INT, target_user_id INT, action TEXT, detail TEXT, created_at INT)
settings(key TEXT PK, value TEXT)   -- 注册开关/默认版本/子域后缀/凭据模式等
```

## 7. 测试计划要点

- **隔离测试**（最高优先）：双用户双实例矩阵——文件互不可见、会话互不可见、URL 越权 404、凭据互不可读；
- **生命周期**：启动超时/端口被抢/dsh 缺失/磁盘满四类失败的快照与恢复；
- **网关**：WS 长连接 8h 稳定性；实例重启后浏览器免刷新恢复；
- **并发**：同用户并发点"新建"不产生端口冲突（PortAllocator 事务性）；
- **升级**：dsh 版本切换（npx 固定版本）后旧会话可恢复。

## 8. 风险与开放问题

| 风险 | 等级 | 缓解 |
|---|---|---|
| dsh 前端在反代后有未知硬编码回环 URL | 中 | M0 S1 全功能走查；必要时网关改写 HTML 绝对 URL（最后手段） |
| 单机多实例内存压力（每实例一个 node + 会话缓存） | 中 | 默认每用户 max_running=1；M5 限额；文档给出实例数/内存经验值 |
| 昵称目录改名连锁（路径可能写进 dsh 会话记录） | 中 | 实例 ID 与目录名解耦（§3.1）；改名默认仅管理员可操作且先停实例再迁移 |
| 管理员接管用户实例的隐私边界 | 低 | 接管需显式开关 + 全量审计；日志默认脱敏展示尾部 |
| dsh 升级破坏监督器假设（参数/行为变化） | 中 | 版本白名单锁定；监督器对 dsh 输出只做弱耦合解析（URL 行可选） |
| trusted-host 通配能力不明 | 低 | 本就计划逐实例传完整子域，S2 仅影响能否共享配置 |
