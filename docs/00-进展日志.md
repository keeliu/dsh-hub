### 3. 脚手架（dsh-hub/，零依赖可运行）与 Spike 执行

- ✅ package.json（spike:s1…s5、dev、build 脚本位）、tsconfig.json（NodeNext + strict + erasableSyntaxOnly）、.gitignore、README.md
- ✅ src/index.ts —— 环境自检引导入口（`pnpm run dev`），内嵌 `sanitizeNickname`（与 §3.1 一致）
- ✅ spikes/s1-reverse-proxy.mjs —— 临时 DSH_HOME spawn dsh web → TCP 探活 → 零依赖反代（HTTP + WS upgrade 裸管道隧道）→ 壳 HTML / 资源 / __DSH_BOOT__ / 单次 RPC / 事件流双路断言。**结果 7/7 PASS**：WS 事件流 `/api/events.mux`、`/api/events.host` 直连与经代理均 101；`POST /api/host.describe` 均 200（首版探测路径错误导致 2 FAIL，修正后全过）
- ✅ spikes/s2-trusted-host.mjs —— 静态分析 trustedHosts 消费点。**结论**：匹配为**精确全等**（WHATTWG 归一化），端口裸条目 = 任意端口；`/api` 围栏叠加同源浏览器标记要求；另有「特权方法回环钉死」发现
- ✅ spikes/s3-systemd-run.sh —— **结论**：非特权 `systemd-run --scope` 被 polkit 拒（`requires interactive authentication`）、`--uid` 同拒、cgroup v2 用户子树不可建；首版脚本属性名错误（PidsLimit→TasksMax）已修
- ✅ spikes/s4-npx-version.mjs —— **结论**：npm registry 可达；npx 冷启动 3207ms/热 2754ms 可行（报告阈值 FAIL 系快速网络下不显著，不阻塞）；首版调用未定义函数已修
- ✅ spikes/s5-nickname-dir.mjs —— **13/13 PASS**：中文目录 roundtrip / 净化规则 / 冲突 -2/-3 / rename / tar 备份全通过

### 4. Spike 验证记录（docs/03-Spike验证记录.md，M3/M5 决策依据）

全部结论与设计影响见 docs/03。**两处重大修正**：①「WS 隧道必需」**成立**（事件流是 WebSocket，普通 GET 回 426）；②「外网不可达」修订为「npm 可达、GitHub 不可达」。**新发现**：特权方法（settings/credentials/agentPreset/host.pickDirectory/llm.discoverModels）在 trusted-host 部署下仍**回环钉死** ⇒ 多用户网关下这些方法 403 ⇒ M1 起默认「管理员模板注入」供给凭据（计划 §3.6 模式 2），M3 验证「Host 重写回环 + 剥 Origin」。
