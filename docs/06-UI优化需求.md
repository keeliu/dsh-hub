# DSH Hub · UI 优化需求

> **版本 v2**（2026-10-11）· 本文件是 DSH Hub UI 改造的**唯一需求清单**。
> **整合说明**：由 UI 优化需求早期草稿 v1 与两份 UI 现状审计（用户端 / 管理端）整合去重而成，**草稿与审计记录已并入本文件并删除、不再单独维护**；**唯一设计依据是 [`design.md`](../design.md)**（下称「规范」，§号即该文档章节），本文只描述「现状缺陷 → 处置 → 验收」，不重复定义视觉值。
> **范围**：用户端（认证页、`/instances`、`/instances/:id`、`/membership`、`/payment/return`、`/profile`、Workspace 外壳）+ 管理端（`/admin/*` 8 页 + 侧边栏）+ 共享骨架与网关注入导航。
> **不在范围**：dsh 实例内部的 DSH Web UI。
> **证据规则**：所有现状结论附 `文件:行号`，来自两轮只读审计（未修改任何文件；因本机无可用 shell 沙箱，未运行 `npm`/`tsc`）。

**需求编号**：`C-xx` 跨端共性 · `U-xx` 用户端 · `A-xx` 管理端 · `D-xx` 数据展示。
**优先级**：**P0** 数据/信任错误或可见破损，必须最先修；**P1** 影响可用性；**P2** 打磨。

---

## 0. 结论速览

现状最要紧的不是「不好看」，而是三类**会误导人的问题**：

| 类型 | 代表问题 | 后果 |
|---|---|---|
| 数据说错 | 管理端订单金额放大 100 倍（`views/admin.ts:456` 未除 100 ↔ `views/user.ts:594` 除 100，同一字段 `orders.amount`） | 管理员/客服按错误金额对账 |
| 操作说假话 | 封禁失败被 `catch` 吞掉后仍无条件 redirect（`pages.ts:646-649`） | 管理员以为封了，实际没封 |
| 界面说没有 | 6 个 CSS 变量 + 6 个 class 未定义（`views/layout.ts:591/596/598/868/1052/1099`、`views/admin.ts:154`、`views/admin.ts:495-557`） | 价格页完全无样式；改样式不生效 |

在此之上，视觉层面的最大落差是三处（规范 §11.1）：**卡片白底+阴影应改为 `#f5f6f7` 填充无阴影**、**输入框 24px 胶囊应改为 8px**、**主按钮蓝底应改为 `#0f1115` 黑底**。这三处一动，全站观感即回到规范。

另有 **4 处结构性缺陷**必须先修，否则后续改动会静默失效（规范 §11.2）：三套设计语言并存、导航高度三个基准值、令牌分叉、未定义引用 + CSS 游离声明。

**工作量估算**：P0 约 1 天，P1 约 3 天，P2 约 3 天（单人，不含评审与视觉回归）。

### C-02 修复主 CSS 语法破损（P0）

`views/layout.ts:197-198`（孤立 `cursor: pointer;` + `}`）与 `:209-211`（孤立 `font-weight: 600;`、`font-size: var(--font-size-base);` + `}`）是游离在规则块之外的声明（`.dropdown-item-danger` 在 `:196`、`.dropdown-divider` 在 `:208` 已闭合）。会让后续解析错位，**任何依赖「后面覆盖前面」的改动都可能静默失效**。

### C-14 骨架语义与页面一致性（P1）

- 现状 `layout()` 只输出 `<nav>` + `<div class="container">`（`views/layout.ts:988`），**无 `<main>`/`<footer>`**（与 `:4` 注释不符）；改 `<aside class="sidebar">` + `<main id="main">` + `.skip-link`（规范 §4.1）。

### C-15 HTML 插值与内联事件安全（P1）

1. **所有 `${}` 插值必须包 `escapeHtml()`**；现状漏转义：`views/user.ts:591`（`order.order_no`）、`:592`（`payment_order_id`）——支付网关字段是外部输入，属合规风险。
2. **禁止把插值放进内联事件处理器的 JS 字符串**：`onsubmit="return confirm('…${escapeHtml(name)}…')"`（`views/user.ts:84`，同款 `views/admin.ts:297`）。`escapeHtml`（`http.ts:40-47`）把 `'` 转成 `&#39;`，但 HTML 属性解析会先还原成裸单引号，含单引号的实例名（实例名无字符集限制，`instances.ts:61`）会让内联处理器编译失败被忽略 → **确认框被静默绕过、表单直接提交**。
3. 替代做法：`data-*` 属性 + 事件委托，或统一使用规范 §5.8 的 `.modal--danger` 组件（同时满足 C-06 的焦点要求）。
4. 外链一律 `target="_blank" rel="noopener noreferrer"`；现状缺 `rel`：`views/user.ts:192`、`:345`。

**验收**：把实例命名为 `a'b` 后点删除，确认框正常弹出且取消后不删除；`grep -rn 'on[a-z]*="' dsh-hub/src/views` 无输出。

### C-16 移动端表单字号与触控目标（P1）

- `font-size:16px` 只写在 `AUTH_CSS`（`views/layout.ts:1074`）→ 非认证页 `.form-control` 仍是 14px（`:296` + `:51`），iOS 聚焦会放大页面。**推广到全部表单页（<768px）**。

- 无 `@media (hover: hover)` 守卫 → 触摸端「粘滞 hover」（`views/layout.ts:262`）。
- `@media (max-width:768px)` 里 `.actions{display:flex}` 无 `flex-wrap`（`views/layout.ts:414-418`）→ 行内「会员设置」表单 + 封禁按钮互相挤压（`views/admin.ts:223-242`）。

## 2. 用户端需求

### U-01 `/payment/return` 页面几乎无样式（P0）

该页引用的 class 全仓库无定义：`payment-return` / `payment-return-icon` / `payment-return-desc` / `payment-return-actions`（`views/user.ts:658-675`）、`membership-badge`（`:666`）、`membership-expire`（`:669`，注意 CSS 里定义的是**复数** `.membership-expires`，`views/layout.ts:721`）；`.payment-qrcode`（`views/user.ts:335/372`）也无定义。

**后果**：支付回跳后用户看到一个近乎裸 HTML 的页面，按钮堆叠。
**处置**：按规范 §4.2 / §5.11 / §6.1 补齐「支付结果页」三态（成功 / 待确认 / 失败）+ 主 CTA；**同时修逻辑矛盾** —— 现状无条件渲染「✓ 支付成功」而下方徽章显示「未激活」（`views/user.ts:659-661`）。
**验收**：`/payment/return?orderId=X` 正常渲染有样式；订单未支付时不显示「支付成功」。

### U-02 表格响应式（P0）

`.table`（`views/layout.ts:322-341`）无溢出容器，实例列表 7 列（`views/user.ts:45-92`）、订单 7 列（`:576-603`）→ **375px 下整页横向滚动**。
**处置**：`.table-wrap { overflow-x: auto; }` 包裹所有表格（规范 §5.4）；<768px 按列数改为卡片列表。
**验收**：375px 下 `document.scrollingElement.scrollWidth <= clientWidth`，且表格内容可完整查看。

### U-03 窄屏导航不可达（P0）

`@media (max-width:768px){ .admin-sidebar{display:none} }`（`views/layout.ts:906`）隐藏了侧边栏却**未提供任何替代导航**：管理端 8 页之间只能靠浏览器返回；`.navbar` 同断点不收窄也不换行（`:899-902`），长昵称无截断（`:933`）。
**处置**：按规范 §4.2 改为抽屉（汉堡按钮 + 遮罩 + Esc 关闭 + 焦点陷阱），或顶部横向滚动导航；昵称加 `text-overflow: ellipsis`。
**验收**：375px 下可从任意管理页一键到达其余 7 个管理页。

### U-04 状态中文化（P1）

`statusBadge()` 未映射的状态直接输出 DB 英文原值（`views/user.ts:34`、`views/admin.ts:66`）。
**处置**：按规范 §5.5 的状态字典映射（`running`→运行中、`stopped`→已停止、`starting`→启动中、`stopping`→停止中、`failed`→失败等），未知状态兜底「未知」而非原文。
**验收**：用户端与管理端所有状态徽章均为中文。

## 6. 验收标准（整体）

1. **数据正确**：同一数据在用户端/管理端/第三方回跳页显示一致（金额、时间、状态）。
2. **操作可信**：每个危险操作有确认，每个操作有成功或失败反馈，**失败绝不显示为成功**。
3. **无静默失效**：无未定义的 CSS 变量/class；无 CSS 解析错误；样式改动可见。
